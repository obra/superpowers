# Superpowers — ldt116 Fork

Fork of obra/superpowers, fine-tuned to change how coding-agent harnesses behave. Install from this repository, not the official marketplaces (see README).

## Tuned Divergences from Upstream

Every intentional difference from upstream is listed here. When merging upstream updates, preserve these.

1. **Planning and execution are phase-split; subagent-driven development remains the default execution mode.** After saving a plan, `writing-plans` hands execution to a fresh session — never the authoring one, whose context carries the brainstorm, the spec, and every plan draft — with a pointer-only prompt (plan file path, worktree/branch, REQUIRED SUB-SKILL: superpowers:subagent-driven-development); the implementing session reads the plan file itself. It still never offers an execution choice. The dispatched session inherits the authoring session's env/config (endpoint, provider, credentials) — never a different account unless the human partner explicitly directs otherwise. One clean-context implementation subagent is the fallback when fresh sessions aren't available; `superpowers:executing-plans` is the fallback for harnesses without subagent access only.
2. **Independent review during inline plan execution.** `executing-plans` runs an independent review after every task — a dispatched reviewer subagent, or a fresh-eyes self-review when subagents are unavailable — plus one final whole-plan review before finishing.
3. **Fork packaging identity.** The marketplace is `superpowers-ldt116` (both manifests; asserted by `tests/codex/test-marketplace-manifest.sh`). Marketplace `owner` is ldt116 and `.claude-plugin/plugin.json` `repository` points at the fork; `author` credits stay with upstream (Jesse Vincent).
4. **Hardened review contract.** Review seats trust code over claims: risk diffs (write paths, auth/secrets/permissions, concurrency, plan-named risks) are re-verified by the reviewer at the review head; other diffs need command-and-output evidence, and prose verdicts are findings. Reviews never approve without requirements ("No — requirements not reviewed"). Implementer reports end with an evidence-based Self-review line, audited by the task reviewer. Deferred debt outlives the workspace (follow-up issue or in-repo debt register). Mutation-verify where runnable.
5. **All skill artifacts live outside the repository, under `/tmp/superpowers/<project-id>/`.** Plans (`writing-plans`) and specs (`brainstorming`) are saved as files under `<id>/plans/` and `<id>/specs/` — never inside the repo (upstream commits them under `docs/superpowers/`), never posted to a tracker. `subagent-driven-development`'s machine-internal artifacts (task briefs, implementer reports, review packages, ledgers) exist only to be run and live in `<id>/sdd/<plan-basename>/`, resolved by `scripts/sdd-workspace`; brainstorm-server sessions live under `<id>/brainstorm/` and are kept on stop so mockups survive (only the no-project `/tmp` fallback is deleted on stop). `<project-id>` is the repo root's basename plus the first 6 hex chars of the root path's md5 (e.g. `superpowers-3f9c2e`) — per checkout, so linked worktrees scope separately. Scratch never dirties `git status`, never lands in a commit, and survives `git clean -fdx`; the durable record is git history plus the debt register, and `/tmp` is accepted as ephemeral. There is no final-summary posting or issue close-out — the final report goes to the conversation, and deferred findings get follow-up issues or a debt-register entry.
6. **Main-chat leanness is a session rule.** `using-superpowers` — injected at every session start — carries a "Keep the Main Chat Lean" contract: the main conversation holds decisions, dispatches, rulings, and conclusions; file contents, command output, and diffs reach it only as targeted extracts (grep hits, ranged reads, redirected-output excerpts) or subagent digests — never bulk payloads. Micro-tested when added: 5v5 reps, control median 133KB ingested into context vs treatment 6.5KB, distributions fully separated with correctness intact. `subagent-driven-development` enforces the same rule at its boundaries: hand-composed dispatches carry the return contract (under 15 lines back, detail in the report file), and tracker-bound bodies — issue comments, PR bodies — are composed as files and posted by path, never inline through string-only tracker tools.
7. **Fork-only on-demand multi-dimension review.** `multi-dimension-review` reviews a git-level target (working diff, `BASE..HEAD`, or branch-vs-base) by dispatching six fixed dimension subagents — correctness, security, code-smells (taxonomy in its `references/`), performance, tests-regression, requirements-conventions — plus a merge/verify seat applying the hardened review contract: risk findings re-verified at HEAD with fresh command-and-output, CONFIRMED/PLAUSIBLE/drop verdicts, and a requirements gate that reads "unverifiable — no requirements provided" when the caller gives no intent — never a silent pass. Report-only: no fix loop, no forge posting. Artifacts under `/tmp/superpowers/<project-id>/reviews/<label>/`; dispatches carry no `model:` field; returns are ≤15 lines. Micro-tested when added: 3/3 salvage-graded reps on no-model-field, ≤15-line returns, evidence per finding; merge-seat criteria (report verdicts + requirements gate) deferred to a follow-up run.
8. **Substantive external-context tasks open with a digest and close with a recap.** `using-superpowers` carries a "Summarize Before Acting" contract: when a task's context lives outside the conversation (issue, PR, review target, bug report), the agent reads it and the code it touches, then gives the human partner one digest — what the task needs, the context that shapes it (current state, constraints, surprises), the approach, judgment calls marked as the agent's own — before asking anything or changing anything, then proceeds without waiting; the completion report opens with a short recap of that same context. Skipped when the conversation already carries the context or the task states itself completely. Micro-tested when added: bug-shaped tasks already digest via systematic-debugging's phase gate (control 5/5, scenario retired per micro-test rule); feature-shaped tasks failed control (1/5 no digest before the brainstorming question, 4/5 decision-logs with thin context in 4 different shapes at scattered positions) and converged 5/5 on one task/context/approach skeleton with the section present.

When this list changes, update the fork section of README.md to match. The README lists behavioral divergences only — packaging identity (#3) stays out of it; the manifests and the test carry it.
